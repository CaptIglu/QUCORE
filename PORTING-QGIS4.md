# QUCORE — Qt6 / QGIS 4 compatibility port

Ported 2026-08-06. **188 changed lines across 15 files.** No behavioural changes intended;
the plugin now runs on both QGIS 3 (Qt5) and QGIS 4 (Qt6) from a single source tree.

## Why it was needed

QGIS 4 ships **PyQt6 only** — there is no `PyQt5` module. QUCORE imported `PyQt5`
directly in 17 files, so it failed at import and never appeared in the plugin manager.

## Changes

### 1. `PyQt5.*` → `qgis.PyQt.*` (14 files)

QGIS ships a compatibility shim (`qgis.PyQt`) that resolves to PyQt5 under QGIS 3 and
PyQt6 under QGIS 4. This covers module-level and function-level imports, plus `QtXml`.
`from PyQt5 import sip` → `from qgis.PyQt import sip`.

The shim also re-exports `QAction`, `QActionGroup` and `QShortcut` from `QtWidgets`
(Qt6 moved them to `QtGui`), so those imports did not need changing.

### 2. Enum scoping (142 occurrences, 47 distinct)

PyQt6 removed unscoped enum access. Verified against the bundled PyQt6:
`hasattr(Qt, 'AlignCenter')` is `False`. The `qgis.PyQt` shim does **not** patch these back.

    Qt.AlignCenter          →  Qt.AlignmentFlag.AlignCenter
    Qt.ItemIsEditable       →  Qt.ItemFlag.ItemIsEditable
    Qt.LeftButton           →  Qt.MouseButton.LeftButton
    QDialog.Accepted        →  QDialog.DialogCode.Accepted
    QMessageBox.Yes         →  QMessageBox.StandardButton.Yes
    QHeaderView.Stretch     →  QHeaderView.ResizeMode.Stretch
    QPainter.Antialiasing   →  QPainter.RenderHint.Antialiasing
    QStyle.SP_ArrowBack     →  QStyle.StandardPixmap.SP_ArrowBack
    QMetaType.Int           →  QMetaType.Type.Int
    ... 38 more

The scoped form is also valid in PyQt5, so this is backwards-compatible. The mapping was
generated by introspecting the live PyQt6 classes rather than hand-written, so it is
exhaustive — see `qt6_enum_fix.py` in the porting scratch files.

### 3. Removed Qt5 APIs

| Change | Sites |
|---|---|
| `.exec_()` → `.exec()` (PyQt5 accepts both) | 8 |
| `QgsMapMouseEvent.pos()` → `.pixelPoint()` (Qt6 removed `pos()`; `pixelPoint()` exists in QGIS 2+) | 3 in `map_tools.py` |

### 4. Latent bug fixed: `sora_volume_widget.py:163`

    - QFont("Arial", 9, QFont.StyleItalic)
    + QFont("Arial", 9, QFont.Weight.Normal, True)

`QFont`'s third argument is **weight**, not style. Under PyQt5 `QFont.StyleItalic` is the
int `1`, so the original silently set weight=1 and the text was never italic. Under PyQt6
it is a proper enum and raised `TypeError` during paint. The replacement makes the text
actually italic, which was the evident intent.

### 4b. macOS: menu bar was completely unreachable (`plugin.py:483`)

    + self.menu_bar.setNativeMenuBar(False)

On macOS Qt makes `QMenuBar` **native** by default — moved to the system menu bar at the
top of the screen. The control panel is a `Qt.WindowType.Tool` window, which never claims
the native menu bar, so *Datei / Einstellungen / Werkzeuge / Hilfe* rendered at **height 0
and were invisible**. Every menu-only feature was inaccessible on macOS, including the
language switch, the parameter dialogs and the import/export entries.

Measured before the fix: `isNativeMenuBar=True, height=0, visible=False`.
After: `isNativeMenuBar=False, height=30`, all four menus present.

This is a pre-existing macOS bug, not a Qt6 regression — it would have affected QGIS 3 on
macOS too. It is invisible on Windows/Linux, where menu bars are non-native by default.

### 5. `metadata.txt`

    - qgisMinimumVersion=3.0     + qgisMinimumVersion=3.38
    - qgisMaximumVersion=3.99    + qgisMaximumVersion=4.99

The 3.38 floor is **pre-existing**, not introduced here: `plugin.py` passes `QMetaType`
values to `QgsField(...)`, an overload added in QGIS 3.38. The declared `3.0` was already
inaccurate.

## What did NOT need changing

The QGIS Python API surface the plugin uses is **fully intact in QGIS 4.2** — verified by
introspection. `QgsMapLayerType`, `QgsSymbol.Fill`, `QgsWkbTypes.Polygon`,
`QgsVectorFileWriter`, `QgsZonalStatistics`, `QgsMapRendererSequentialJob`,
`QgsVectorLayerSimpleLabeling`, `QgsTask` all still exist.

`QDomDocument.setContent()` still returns the 4-tuple `(ok, msg, line, col)` under PyQt6,
so the two XML handlers were unaffected.

There are no `.ui` or `.qrc` files — all UI is hand-written Python, so nothing needed
recompiling. There are no third-party dependencies; the `.docx` reports are built with
`zipfile` + the bundled XML templates, not python-docx.

`QVariant.Int` in `zonal_stats_calculator.py` was left as-is: the `qgis.PyQt` shim
monkey-patches `QVariant.Int = QMetaType.Type.Int` under Qt6, and this form also works on
QGIS 3 releases older than 3.38. Both forms were confirmed to produce an identical
`QgsField`.

## Verification

All of the following were run headless against **QGIS 4.2.0 (Qt 6.11.1)** and
**QGIS 4.0.3 (Qt 6.9.3)** — green on both:

- byte-compile of the whole tree with QGIS's Python 3.12
- import of all 23 modules
- construction **and a forced paint pass** of all 9 dialogs/widgets
- full plugin lifecycle with a mock `QgisInterface`:
  `classFactory` → `initGui` → `run` → `rebuild_and_calculate` → `unload`,
  producing all 8 SORA layers (FG, CV, GRB, Adjacent Area, VLOS, waypoints, flight path,
  pilot position)
- export → re-import round-trip for all 6 file formats
  (KML, GeoJSON, DIPUL, SkyDemon `.flightplan`, QGC `.plan`, ArduPilot `.waypoints`)
- SORA `.docx` generation — valid zip, 19 parts, 23 KB `document.xml`

**Not verified:** the QGIS 3 / PyQt5 side. No PyQt5 exists on the machine this port was
done on. Every construct used is documented as valid in PyQt5 5.12+ (scoped enums,
`.exec()`, `QFont.Weight`, `pixelPoint()`), but it has not been executed there. Worth a
smoke test on a real QGIS 3.38+ before relying on the dual-compat claim.

## Unrelated observation

`formats/ardupilot_handler.py` (~line 290) guards on `'QUCORE.buffer_calculator' in
sys.modules`, but the package folder is `QUCORE-main`, so that branch never fires. It is
harmless — `BufferCalculator.BUFFER_SEGMENTS` is saved and restored correctly on the class
itself — but the module-level lines are dead code. Not touched as part of this port.

# Post-port bug audit

Beyond the port itself, the following was checked. Findings are ordered by severity.

## Fixed

1. **macOS menu bar invisible** — see §4b above. Severity: high (all menus unreachable).
2. **`QFont` italic never applied** — see §4 above. Severity: cosmetic.

## Found, not fixed (needs the author's domain judgement)

3. **`stallVelocity` never reaches the buffer maths.** It is read in
   `altitude_table_dialog.py:504` and printed into the SORA report
   (`report_generator.py:237`), but `buffer_calculator.py` never references it. Perturbing
   it changes no buffer, for either UAS type. For a fixed-wing aircraft, stall speed is
   normally what bounds the contingency manoeuvre. This may be deliberate under the chosen
   SORA method — worth asking Tim Strohbach before treating it as a defect.

4. **Antimeridian / polar degeneracy.** A route crossing ±180° longitude produces buffers
   ~5000x too large (FG area 1.6e-1 vs 3.2e-5 for an equivalent short route); waypoints at
   latitude 89.9 similarly blow up the Adjacent Area. Irrelevant for European operations,
   but it fails silently rather than warning.

5. **Non-numeric parameter values pass through unvalidated.**
   `ConfigManager.get_param({'maxWindVelocity': 'abc'}, ...)` returns the string `'abc'`
   unclamped; the failure then surfaces as a `TypeError` deep in the maths. Numeric strings
   (`'15.0'`) are handled correctly. Only reachable via a hand-edited `config.json`.

6. **Dead code**, `formats/ardupilot_handler.py` ~line 290: guards on
   `'QUCORE.buffer_calculator' in sys.modules`, but the package is `QUCORE-main`, so the
   branch never fires. Harmless — the class attribute is saved/restored correctly.

## Checked and found sound

- **Parameter clamping works.** `parachuteDescentRate=0` clamps to the 0.1 floor from
  `config_limits.json`, so the `v_z > 0` guard in the Parachute GRB branch is never hit and
  the buffer cannot collapse to zero. Missing keys fall back to defaults correctly.
- **Parameter sensitivity matches SORA.** `maxRollAngle` affects only fixed-wing;
  `maxPitchAngle` only multirotor; `glideRatioDenominator` only under the *Glide* GRB
  method (10 → 40 scales the GRB ~10x); asymmetric wind drift only when explicitly enabled.
  Parameters that appeared inert were all legitimately method- or airframe-gated.
- **Degenerate inputs do not crash**: empty waypoint list, single waypoint, duplicate
  waypoints, zero/negative/extreme altitudes, zero speed — all return valid or cleanly
  empty geometry. No exception raised in any of 18 edge cases.
- **No remaining unscoped Qt enums**, and no dynamic (`getattr`/`eval`) enum access that
  static rewriting could have missed.
- **No Windows-only calls** (`os.startfile`, backslash paths). Help opens via
  `QDesktopServices.openUrl(QUrl.fromLocalFile(...))`, correct on macOS.
- **Export extension handling** is explicit and filter-aware, so a macOS save dialog
  without a typed extension still produces the right format.

## Known macOS behaviour, not a bug

The control panel is a `Qt.WindowType.Tool` window. On macOS such windows are floating
panels that **hide automatically when QGIS is not the active application** and reappear on
return. This is standard Qt/macOS behaviour, not a fault.
